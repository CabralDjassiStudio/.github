# Governance

This is the default governance model for repositories maintained by Cabral
Djassi Studio. Repository-specific governance takes precedence.

## Principles

- clear ownership and accountability;
- decisions based on product purpose and user impact;
- security, privacy, accessibility, and maintainability;
- documented reasoning for consequential changes;
- proportional process according to risk;
- respect for licensing and confidentiality.

## Roles

### Organization owners

Manage organization security, access, visibility, policies, and repository
lifecycle.

### Repository maintainers

Manage architecture, roadmap alignment, reviews, releases, security triage,
documentation, and repository health.

### Contributors

May propose issues, documentation, code, designs, or tests according to
repository rules. Contribution access does not imply ownership, employment,
partnership, or authority to represent the Studio.

## Significant decisions

The following require explicit review and documentation:

- authentication, authorization, and data-access changes;
- breaking API or data-model changes;
- major architecture changes;
- repository publication or visibility changes;
- licensing and intellectual-property changes;
- production migration or data deletion;
- material privacy, accessibility, or contractual changes.

The designated repository or organization owner makes the final decision when
consensus cannot be reached.

## Repository lifecycle

- **Active**
- **Maintenance**
- **Experimental**
- **Archived**
- **Private/Internal**

## Changes and releases

Use pull requests, automated checks, review, and release notes appropriate to
the project's risk level.

Direct changes to protected production branches should be exceptional,
authorized, and traceable.

## Licensing

Follow [`LICENSING_POLICY.md`](LICENSING_POLICY.md). License, ownership, and
brand permissions may not be changed without explicit approval.
