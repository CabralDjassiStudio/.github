# Security Policy

Cabral Djassi Studio asks users, researchers, partners, and contributors to
disclose vulnerabilities responsibly.

## Supported versions

Unless a repository says otherwise, security support is generally limited to:

- the current production release;
- the latest maintained release branch;
- the default branch when no formal release exists.

Archived, experimental, demonstration, and end-of-life projects may not receive
security updates.

## Reporting a vulnerability

**Do not report vulnerabilities through public issues, discussions, pull
requests, commits, or social media.**

Use:

1. GitHub Private Vulnerability Reporting, when enabled.
2. An official private contact channel available on the
   [Cabral Djassi Studio website](https://cabral-djassi-studio.vercel.app/).

Include:

- affected product, repository, version, and environment;
- vulnerability type and possible impact;
- reproduction steps or a minimal proof of concept;
- logs or screenshots with secrets removed;
- possible mitigations;
- whether the report was shared elsewhere.

## Responsible research

Good-faith testing should:

- avoid privacy violations, disruption, and data destruction;
- use the minimum access and data necessary;
- stop after accessing non-public data;
- avoid phishing, social engineering, denial of service, and high-volume attacks;
- not retain, disclose, or exploit obtained data;
- allow reasonable time for investigation and remediation.

## Normally out of scope

- unvalidated automated scanner output;
- missing headers without demonstrated impact;
- self-XSS;
- clickjacking without sensitive actions;
- theoretical rate-limit concerns without practical impact;
- attacks requiring unrealistic victim behavior;
- denial-of-service or social-engineering tests.

## No automatic bounty

This policy does not create a contractual service-level commitment, safe-harbor
agreement, or bug-bounty obligation.
